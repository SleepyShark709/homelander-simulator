## 1. 执行原则与技术决定

规划时目录为空；现已建立 TypeScript、Three.js 和 Rapier 工程。先做可运行的小闭环，再扩展内容，最后按完整场景验收。中间允许灰盒定位和调试，最终必须换成真实模型与动画。

| 层次 | 选型 | 用途与理由 |
|---|---|---|
| 语言与构建 | TypeScript + Vite + npm | 静态浏览器项目，类型检查、快速本地启动与生产构建 |
| 3D 渲染 | Three.js WebGLRenderer | 直接管理场景、模型、动画、镜头和光束；基线使用 WebGL2 |
| 物理 | @dimforge/rapier3d-compat | WASM 物理、角色碰撞、射线/形状查询、车辆和尸体冲量 |
| UI | HTML/CSS + 少量 TypeScript | 加载、HUD 和菜单；场景不使用 DOM 绘制 |
| 资源格式 | glTF / GLB | 模型、骨骼与动画的导入目标格式 |
| 验证 | Vitest；浏览器手动场景验收 | 规则测试覆盖热度、伤害与重置；真实输入、画面与性能在浏览器验证 |

这是本项目的工程选择，并非用户限定的技术栈。Three.js 提供 WebGL 渲染及 GLTFLoader；Rapier 提供场景查询，兼容包仍需等待 WASM 初始化。来源：[Three.js 渲染器](https://threejs.org/docs/pages/WebGLRenderer.html)、[GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)、[Rapier 查询](https://rapier.rs/docs/user_guides/templates/scene_queries_ray_casting/)、[Rapier JS 初始化说明](https://github.com/dimforge/rapier/blob/master/website/docs/user_guides/templates/getting_started_js.mdx)。

Vite 提供 TypeScript 模板、本地服务与静态构建，详见 [官方指南](https://vite.dev/guide/)。实施开始时选择相容的稳定版本，固定依赖并提交锁文件，记录实际 Node/npm 版本，不在文档中猜测未来具体版本。

默认主要验收浏览器为 macOS Chrome 稳定版；Safari 做启动、控制与模型加载冒烟检查。浏览器版本及 M2 内存规格在实际测试时记录，不把不同机器的结果代替目标设备实测。

系统通过明确函数和带类型事件协作，无需提前引入通用 ECS 或插件框架。渲染节点不作为生命值和追捕状态的唯一存储。

### 3.1 核心数据约定

- `EntityId`：每次世界构建内唯一；事件携带 `worldGeneration`，旧世界异步回调不能写入重置后的世界。
- `Damageable`：生命值、目标类别、存活/损毁状态、物理句柄；死亡/摧毁为一次性状态转换。
- `AttackHit`：攻击实例 ID、来源、目标、命中点、伤害、冲量方向。伤害由 DamageSystem 统一结算。
- `PlayerAction`：记录主动攻击，重置追捕安静计时；`DamageApplied`、`Killed`、`Destroyed` 用于有效热度加分。敌人事件不可误归因给玩家。
- `SpawnBlueprint`：初始变换、模型 ID、物理定义和实体配置；重置从蓝图重建，而不是逐个手工修复损毁对象。
- `DestructibleState`：完整 → 受损 → 摧毁；建筑面板摧毁后移除对应碰撞体，车辆损毁后保留物理外壳。

## 4. 核心实现约束

### 4.1 时间、输入与物理

- 物理固定步长 1/60 秒，渲染插值；每帧子步数有上限，后台暂停后不补算长时间积压。
- 输入在帧中采样、动作边沿排队，在固定步中消费一次；伤害、AI、追捕与清理使用游戏时间，不能依赖失焦后仍运行的散落计时器。
- 玩家用运动学胶囊，行走进行落地与坡面检查，飞行关闭主动重力；使用 swept shape/形状扫描处理位移，不能只判断终点是否穿墙。
- 高速车辆开启必要的连续碰撞检测；角色碰撞查询覆盖飞行和冲刺，不能假设动态刚体 CCD 自动解决运动学穿透。
- 物理碰撞层区分玩家、活体 NPC、静态主体、可破坏面板、车辆、尸体、碎片和传感器；视觉光束本身没有实体碰撞。

### 4.2 镜头与攻击

- 从角色附近锚点到理想相机位置扫描，遇墙缩短镜头距离；对角色自身做查询过滤。
- 准星射线确定目标；双眼挂点到目标分别检查遮挡，视觉显示两束光，逻辑作为同一次攻击，避免双倍伤害。
- 镭射连续显示但以 10 Hz 结算伤害，使用实际游戏时间累计，掉帧不能导致伤害翻倍。
- 重拳使用前方短距离形状查询；砸地用落点半径查询并逐个检查遮挡；冲刺使用扫掠路径检测与目标命中集合。
- 撞碎面板后重新检查剩余位移；建筑框架和后方实体仍能阻挡，禁止一旦面板破裂就穿过整栋建筑。

### 4.3 NPC、路网与追捕

- 小街区使用手工标注人行路网和巷道连接，局部障碍避让；飞行玩家的位置投影到合法接近点，AI 不追进建筑内部。
- 日常决策 5–10 Hz，移动随固定步更新；射击需射程和视线检查，枪声不在本版范围，使用枪口与曳光表达。
- 死亡时注销导航和射击，替换为简化动态身体，保留渲染模型并施加冲量；资源池控制尸体上限。
- 出生点先测距离、相机视锥与遮挡，再确认导航及物理空间；没有合适点就延迟，不能为凑人数生成在视野内。
- 升级按目标总数补兵，降级让超额敌人进入撤离状态；撤离后或视野外清理。所有预算计算包含尚未完成的出生请求。

### 4.4 破坏、资源和重置

- 建筑视觉主体与可破坏面板分离，碰撞使用墙段/框架组合；至少有一处缺口可真实穿行、一处露出空腔。
- 碎块用预制小刚体，静止后休眠并按生命周期释放；废车持续保留但可休眠。
- 重置顺序：暂停并清输入 → 递增世界代数、取消旧请求 → 清系统实体与物理世界 → 保留可复用资产缓存 → 按蓝图重建 → HUD 归零。
- 渲染网格共享几何和材质时使用引用管理；删除单个实体不能释放其他实体仍在使用的资源。最终退出时统一释放缓存。

## 5. 分阶段执行任务

以下为阶段任务定义；完成状态维护在 [PROGRESS.md](./PROGRESS.md)。每阶段结束更新验证记录，保留可试玩状态；不要把后续阶段的占位逻辑记为已完成。

### P0 · 工程与素材可行性（对应 A01、A14）

- T01：建立 Vite + TypeScript、版本锁定、类型检查、测试和构建命令；完成 Three.js 渲染及 Rapier 异步初始化，加载失败可重试。
- T02：导入一栋建筑、一辆车和一个可动画人形，记录素材账本；验证双眼挂点、飞行与出拳姿态、单位比例与基本光照。
- T03：建立模型预览场景、简易地面和帧时间面板，确认 M2 浏览器可以加载和交互。
- 出口：真实人形模型与最小动画可见，模型来源和转换路径清楚，开发与生产构建都能启动。人形不可用必须在此解决，不能推迟到最后换皮。

### P1 · 移动与镜头（依赖 P0；A02、A03）

- T04：实现输入、锁定/释放鼠标、暂停/继续、失焦清输入。
- T05：实现步行、冲刺、悬停、升降、加速飞行、自然下落和屋顶落地，接入主角动画。
- T06：实现相机避障、准星、水平与顶部柔和限位，高速完整墙体碰撞。
- 出口：能在有不同高度建筑的测试区完成完整移动流程；高速迎面与斜向撞墙不穿透，不被边界困住。

### P2 · 四能力战斗闭环（依赖 P1；A04–A08）

- T07：实现统一伤害、攻击归因、目标去重、死亡和损毁事件，加入一个活体 NPC 靶和物件靶。
- T08：实现双眼持续镭射及遮挡，地面和空中命中一致。
- T09：实现重拳、砸地、高速碰撞伤害，动作互斥和冲量反馈。
- T10：实现 NPC 简化物理死亡、少量血液、命中特效和生命周期。
- 出口：四种能力都可以杀死 NPC，镭射和范围攻击不隔墙生效，效果清理不重复结算。玩家始终无敌。

### P3 · 完整街区与局部破坏（依赖 P2；A03、A06、A07、A11、A14）

- T11：搭建约 200 × 200 米地图、道路、屋顶、巷道与背景，达到 MVP 场景内容预算。
- T12：接入墙面/窗户预切破坏、缺口碰撞更新、小物件损毁。
- T13：接入停放车辆动态物理、击退、掀翻、损毁外观和车辆碰撞伤害。
- 出口：至少 8 处破坏区域、8 个小物件、6 辆车辆可验证；主体保持完整，缺口能通过或能看见空腔，所有最终环境模型已接入。

### P4 · 活街区与追捕（依赖 P3；A08–A10、A12）

- T14：搭建路网、约 20 名平民日常行走/逃跑与视野外补充，处理死亡注销与导航避障。
- T15：实现热度、三档追捕、安静计时与衰减；将攻击/击杀/破坏事件接到系统。
- T16：接入警察和士兵模型、追击/射击、分批补兵与撤离，最高敌人总数约 12。
- 出口：可从安静街道连续玩到三级追捕，再停止攻击恢复平静；玩家飞到屋顶或空中时敌人行为仍合理。

### P5 · 完整流程与视觉收口（依赖 P4；A01、A13、A14）

- T17：完成中文加载、开始、操作提示、准星、追捕、边界提示、暂停和重置。
- T18：完成世界蓝图重建与异步取消，连续三次重置和失焦恢复验收。
- T19：统一材质、尺度与光照，补齐主角动作/披风、NPC 射击姿态和全部能力反馈，移除永久占位资源。
- 出口：从启动到重置可完整游玩；没有声音，没有新增未确认玩法，所有已确认表现可见。

## 6. 性能预算与验证方法

以下是工程目标，未实测。首次优化先限制渲染分辨率和无用特效，再调整资产复杂度；不得直接移除四能力或三级追捕。

| 项目 | 初始预算 |
|---|---|
| 画布内部像素 | 最长边不超过 1920，像素比上限 1.5；避免直接按 Retina 全分辨率渲染 |
| 活体 | 20 平民 + 12 敌人 |
| 尸体／动态碎片 | 上限 12／60，超限回收最旧者 |
| 车辆 | 6–10，休眠启用 |
| 光照 | 环境光 + 单个方向光；仅近处关键对象投影，避免多盏实时阴影灯 |
| 模型 | 静态重复物件合批/实例化；背景简化；模型复杂度以帧时间测试决定 |
| 特效 | 粒子/血液池化，有数量上限；不默认加入全屏重后处理 |

性能记录使用实际帧时间，区分 CPU 更新和渲染指标。连接电源、关闭低电量模式，记录 macOS、浏览器、M2 型号、内存、窗口和内部渲染分辨率；先预热 30 秒再采样。

1. 常规场景 120 秒：20 名平民日常行走，玩家步行、飞行、转镜头。目标帧时间中位数 ≤18.2 ms（约 55 FPS），P95 ≤25 ms。
2. 压力场景 120 秒：最高追捕，持续镭射、砸地、翻车和破坏；目标中位数 ≤22.2 ms（约 45 FPS），P95 ≤33.3 ms，不能持续卡死或输入失效。
3. 持续游玩 10 分钟，期间重置三次：记录实体、刚体、效果池和可观察内存趋势；数量应回到基线或稳定上限，不能持续增长。
4. 任一性能目标不达标：保留原始结果，记录调整项与复测结果；不能仅展示空场景最高 FPS。

压力场景指标是实施默认容忍范围，不将“常规接近 60 FPS”偷换为始终只有 45 FPS。
