## 1. 建议采用的分工

**Blender 建立空间、结构和模块；Tripo 尝试少量复杂车辆外观基模；Three.js 负责组合、材质表现、实例化和游戏交互。**

这张参考图的主要辨识度来自铜红色办公楼群、街巷与广场、道路断面和滨河绿带。它们首先需要一致的尺度、连续的通行空间、可复用立面和明确的碰撞边界。规则几何所占比例很高，因此没有必要把整栋楼、整条街或每件道具都送去生成。

本轮按四项要求做选择：

1. **外形获得成本**：车辆曲面外壳值得尝试生成；电箱、罐体、花池等少量规则形体直接建更快、更可控。
2. **几何精度与编辑需求**：门窗间距、楼层高度、道路与桥梁连接、可破坏面板必须可精确编辑。
3. **复用方式**：同一窗格、路缘或护栏应重复使用统一模块；避免每次生成不同的接缝与尺寸。
4. **实际游戏用途**：静态外观、动态刚体、破坏部件和蒙皮角色的要求不同。Tripo 输出不自动等于可以交付游戏的最终模型。

上述工具选择是针对本图和当前 Web 游戏的工程判断，尚无这些新资产的 Tripo 生成成功率或游戏运行测量。

| 编号 / 优先级 | 建议生产范围 | 为什么值得尝试 Tripo | Blender 必须完成的部分 | 首批数量与取舍 |

| **T03 / 可选**：蓝黑色两轮车 | 只有在确认要做踏板式电动车时，尝试车壳、挡泥板、坐垫等较厚实的外观部分 | 曲面塑料外壳可生成基模；细车架的收益较低 | 车轮、前叉、车把、脚撑、轮轴和细杆按规则重建；检查空隙、轮径、对称与地面接触；替换糊成一体的细节 | **可选一款**。图中车型与后侧结构不清楚，需先补单体设计。若最终选普通自行车/共享单车，优先直接在 Blender 搭建 |

## 4. 适合 Blender 直接搭建的资产

| 资产组 / 参考板位置 | 建议建法与拆分 | 选择依据 / Three.js 接入要点 |
|---|---|---|
| **城市总布局、地形** / 01–03 | 先确定道路中线、地块、建筑占地、地面与屋顶高度、河岸；建立统一白模布局 | 全景和俯视图之间不能自动视为精确一致；先用一份布局消除冲突，再从它导出各视角 |
| **元中心办公楼** / 01–05 | 拆成楼体、首层入口/架空层、标准层、窗格、幕墙竖梃、女儿墙、屋顶设备；Array/Geometry Nodes 组织重复构件 | 办公楼的价值在比例和立面节奏；需要规整接缝、真实入口与可站立屋顶。不要把所有立面细节都做成高密度几何 |
| **灰白办公楼与住宅远景** / 01–03 | 少量楼体原型＋不同高度/立面组合；中远景简化层级 | 重复体量与共享材质便于扩展背景，避免生成几十栋无法统一尺寸的独立楼 |
| **临街店面、小砖房** / 05、07 | 墙、檐口、门框、玻璃、卷帘门、招牌面、室外空调、管线分开；近景增加浅室内或内腔 | 可破坏玻璃和可进入缺口需要独立视觉/碰撞结构，不能被整栋粗碰撞盒封死。招牌文字作为可替换贴图处理 |
| **道路、路口、路缘、人行道** / 01、03、04 | 按统一道路断面搭建；车道线/斑马线独立贴花或薄面；道路和铺装分区 | 需要连续地面与稳定碰撞。沿用本项目“地表不重叠”的规则，避免飞行和行进时闪动 |
| **桥梁、河岸、挡墙、坡面** / 01–03、06 | 梁板、桥墩、栏杆、挡墙、岸坡分件，护栏使用重复模块 | 必须保证桥墩支撑、通行宽度、坡道和水面高度一致；岸线与街区坐标应由统一布局确定 |
| **河流水面** / 01、02、06 | Blender 提供河床/岸线与低密度水面几何；Three.js 控制水材质、法线运动及反射策略 | 水的观感依赖实时材质和光照；不需要生成带固定反射与波纹阴影的实体水块 |
| **交通灯、路牌、公交站、护栏** / 04、06 | 盒体/圆柱/曲线加重复组件；灯壳、杆、牌面分开 | 高度、方向、文字和间距需要准确；规则组件复用收益高。交通灯的亮灭交给运行时材质 |
| **银色工业奶罐装置** / 01、05 | 圆柱、封头、支腿、短管线组合；主要轮廓先建，接缝和磨损用材质补充 | 本图表现的是规则罐体，不是复杂自由曲面雕塑；直接建能控制尺寸与管线连接。若后续设计改成复杂雕塑，再另行评估 |
| **电气柜、空调外机、花池、座椅基础** / 05、07 | 电箱用盒体＋倒角；空调采用壳体和格栅；花池拉伸截面；重复座椅复用组件 | 图中对象几何简单；门缝、风扇、格栅可按观察距离使用贴图/法线。无需为外观纹理重新生成整件网格 |
| **黄色共享自行车** / 07 | 曲线生成车架，统一车轮/轮胎，复制前后轮；链条/辐条依据距离简化 | 细管、轮圈空隙、细辐条的规则性比生成纹理更重要。中远景可大幅简化辐条 |
| **梧桐/阔叶树、柳树、灌木** / 01、05、06 | Blender 曲线或 Geometry Nodes 制作树干/枝条；枝叶卡组合成枝簇/树冠，制作不同距离版本 | 需要可控轮廓、透光和重复实例；大量叶片不宜变成封闭实体叶团。梧桐与柳树应有不同枝型和叶卡，不把同一树冠简单拉伸成柳树 |
| **破坏面板、碎玻璃、损毁道具** / 游戏交互部分 | 从最终完整模型派生独立面板、预切碎片和状态版本；制作简化碰撞 | 破坏范围、缺口与物理连接必须明确；完整模型、受损模型和碎片保持同一局部坐标 |

当前 MVP 可玩区域约 200 × 200 米，参考板呈现的是更大城市概貌。建议先选择路口、部分园区与一段滨河作为核心布局，其余作为背景层；扩大可玩地图时另定范围，不能按参考图全景直接默认为完整可玩城市。

## 6. Tripo 输入应如何准备

参考板只用于确认位置、颜色、类型和风格。04 面板中的轿车单体约几十像素宽，公交约百像素；07 面板中的两轮车还受到遮挡。直接裁切并放大不会补回真实的结构信息。

对决定制作的每个对象，先准备：

1. **一张单体主参考**：干净背景、完整轮廓、无人骑乘/无遮挡、自然均匀光照；建议单独制作约 1024 像素参考，避免把街道和行人带进模型。
2. **必要的补充视角**：同一款物体的正面、侧面和背面，保证轮轴、车门、灯组、尺寸与材质相互一致。不是从场景板里随意找几辆不同车辆凑成多视图。
3. **用途与结构说明**：静态/刚体、是否需要独立车轮、是否可破坏、是否需要内腔；先把本轮真正需要的结构说清楚。
4. **尺寸基准**：轿车可先以长约 4.5 米为布局估计，再根据选定造型修订；公交与两轮车先确认车型。尺寸是制作约定，不是从本图测得。

Tripo 官方支持多视图输入，并要求同一对象、相近光照；提供重拓扑和目标面数相关处理。它们可作为生产步骤，仍需检查输出的尺寸、轮廓、部件与 UV。官方功能描述不保证本图某个资产一定生成合格。来源：[Tripo 多视图文档](https://developers.tripo3d.ai/en/docs/generation-multiview-to-model/standard)、[Tripo 重拓扑文档](https://developers.tripo3d.ai/en/docs/mesh-decimate)。

## 7. Blender 到 Three.js 的交付约定

以下为拟采用的生产起点，并非已验收预算：

- **尺度与朝向**：米制；Blender 可以按自身 Z-up 编辑，导出 glTF 时转换至 Y-up；物体应用缩放，车轮/门/破坏片保留正确局部原点和命名。
- **材质**：把金属、油漆、玻璃、轮胎和灯的行为区分开；清理生成纹理中的固定投影/高光；不把玻璃后方的街景烘成车窗颜色。
- **网格**：检查孔洞、法线、薄片和重叠面；删除不影响轮廓的隐藏几何；对可近看的曲面保留足够轮廓精度。
- **候选轿车预算**：可先以近景约 1–2 万三角面、远景逐级降低、1–2K 主纹理作为试制范围；材质槽尽量少。实际质量和成本要在当前游戏里判断，不机械追求某个面数。
- **文件**：保留原始生成结果、Blender 源文件、导出 GLB 和来源记录；运行时优先使用 GLB；若以后启用压缩，需要同步配置对应解码器并检查画面。
- **重复对象**：同款窗格、路灯、路缘、树或静态车辆共享几何与材质；依据部件结构选择实例化或合批。Three.js 的 `InstancedMesh` 适用于共享 geometry/material 的重复对象，见[官方说明](https://threejs.org/docs/pages/InstancedMesh.html)。
- **交互**：可破坏面板与动态刚体拥有独立状态/碰撞；共享资源不能随单个实体销毁而误释放。车辆碰撞体采用简化凸体组合，不直接用高密度渲染网格替代。

## 8. 建议的首批制作顺序

1. **锁定白模布局**：在 Blender 确定路口、园区入口、建筑占地/高度、桥、河岸和主步行路线；从同一布局复核全景和俯视。
2. **制作最小建筑模块组**：办公楼一组、住宅一组、店面一组，先打通标准层/入口/屋顶与破坏面板；复用现有 PBR。
3. **只试制 T01 一款轿车**：先单体参考，再 Tripo 基模，再 Blender 清理、拆件、碰撞和损毁版本，最后导入游戏观察。
4. **复用陈设并完成近景**：路灯、桌椅、卷帘门、花池、奶罐、电箱、交通设施和植被。
5. **按确认结果增加 T02/T03**：公交以静态装饰需求为起点；两轮车先确定是踏板式电动车还是细管自行车。

首款模型需核对正/侧/背/俯视、实际近景/飞行观察、轮地接触、遮挡、车辆刚体互动和重置。新参考图及生成预览不替代游戏内验收。本轮未启动建模、Tripo 服务或额外性能测试。
